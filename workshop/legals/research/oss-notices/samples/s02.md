## Document
- Shape: one very long HTML page (about 66K lines of plain text) inside the marketing site's header and footer. A generated npm block list comes first: 1,182 blocks, no table of contents, no anchors. Below it are four hand-written sections under `=====` banner headings for non-npm components (Rust, Go, native C++, ML runtime and models).
- Generator: `generate-license-file` (npm), named on the page with a link. The tail sections are added by hand after the generated output (different separators, all-caps banners, own provenance prose).
- Register: no company voice at all apart from the generator line and the hand-written provenance notes in the tail. No preamble, scope statement, disclaimer, contact, or source-code offer from Granola. The GPL/LGPL "written offer" wording appears only inside the reproduced licence texts.
- Per-entry fields (npm part): package name@version (one or several per block), then the full licence text as shipped by the package. Licences are never shown as SPDX ids in this part. Each block ends with an 11-dash rule. Blocks: 821 single-package, 361 grouped (packages sharing an identical licence text), about 3,180 package lines.
- Per-entry fields (tail): Rust and Go entries are name(@version) plus an SPDX expression, with no texts. C++ and ML entries are a component heading between dashed rules, then copyright and full licence text. Model entries add file name, source repo/revision, licence of the training data, changes made, and an attribution line.
- Recurring elements: no date, no version of the app, and no "last updated". The only Granola-dated element is the page footer copyright. Embedded upstream notices are kept whole: Microsoft's ONNX Runtime third-party notices, including Microsoft's $5 source-by-mail offer, and the LLVM licence block.
- Scope: the desktop app (Electron/npm bundle, Windows native module and helper binary, on-device audio/ML components). Mobile is not addressed.
