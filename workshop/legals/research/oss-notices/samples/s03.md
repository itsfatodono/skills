## Document
- Shape: one long HTML page of cards: header with generation metadata, a compliance disclaimer,
  a licence glossary, then one component table per build target (frontend npm, backend npm,
  Docker images, CDN assets), an Apache NOTICE card and a footer pointing at plain-text bundles.
  About 400 entries; most of the word count is per-package licence excerpts in collapsible
  blocks.
- Generator: `license-checker` over the production dependency tree, named in the lead, with a
  UTC generation timestamp and the npm script that regenerates the page. Page template is the
  developer's own (i18n keys, EN / Traditional Chinese switcher; English is the default HTML
  and the version taken).
- Register: technical, impersonal, addressed to a maintainer or distributor rather than the end
  user; exposes internal paths (container paths, repo docs file, npm script).
- Recurring elements: generation timestamp; links to companion files `/THIRD_PARTY_NOTICES.txt`
  and `/APACHE_NOTICES_aggregate.txt` (both live); "not legal advice" disclaimer; back link to
  the web app's login.
- Per-entry fields (npm tables): package@version, SPDX licence expression, publisher (name or
  email), repository URL or "—", and a collapsible "LICENSE excerpt" holding the package's
  licence file as read at generation (sometimes the README when no LICENSE file exists).
  Frontend 161 entries (MIT 130, ISC 16, Apache-2.0 6, BSD-3-Clause 4, one UNLICENSED, a few
  compound expressions); backend 228 entries (MIT 189, Apache-2.0 17, BSD-3-Clause 11, ISC 7,
  single BlueOak, MIT-0, 0BSD and others).
- No source-code offer, no copyleft handling beyond telling the reader to review it, no contact.
