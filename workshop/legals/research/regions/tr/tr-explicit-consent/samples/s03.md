## Document
- Shape: one standalone web page, separate from the KVKK notice; version block on top, nine short headed sections, a closing affirmative statement in quotes. A layered consent: one general health-data consent plus features that each need their own, separate opt-in (AI transfer per use, dietitian sharing, weekly check-in sending).
- Register: first person from the user ("işlenmesine açık rıza gösteriyorum", "silebilirim"), the controller named in the third person by name; plain, concrete, product-specific (names screens, toggles, retention days).
- Recurring elements: version id, effective date, status and last-updated note with a change summary; a "not pre-ticked" statement; default-off statements for every optional feature; retention and deletion trigger stated per data type; withdrawal channel (in-app settings, email).
- Consent items and acceptance:
  1. General health-data consent. Asked for: processing (no transfer) of health/fitness data the user enters or links (meals, calories/macros, weight and body measures, goals, water, allergy, diagnosis, medication/supplements, lab documents, HealthKit) for five listed purposes (tracking, insights/reports, AI answers, dietitian features if enabled, sync/backup). Recipient: the controller only. Taken by: an unticked checkbox, with the closing quoted affirmative statement.
  2. AI features and transfer abroad. Asked for: sending named content per feature (question plus optional profile and dietitian-plan data, typed log line with local time, meal photo) to a named foreign processor (Google LLC, Gemini API) outside Türkiye; lists data never sent and the processor's use limits. Taken by: bundled in the same checkbox, worded as consent renewed on each use of an AI feature; the user can avoid it by not using the features. Two profile-sharing toggles inside it are separate and default off.
  3. Dietitian sharing. Asked for: making chosen data categories (meals, weight, water, activity, health profile, lab results, HealthKit, check-ins) visible to one chosen dietitian for a fixed 28-day window, including past records. Recipient: the dietitian, via the controller's server. Taken by: a separate in-app approval when connecting to a dietitian, per-category toggles; this text does not grant it.
  4. Weekly check-in sending. Asked for: sending progress photos, weight/waist, mood and a note to the dietitian; 12-week server retention. Taken by: a separate approval page shown on first tap of "send to my dietitian", which adds a sharing category; default off, explicitly not switched on by this text.
  - Not asked: advertising, cross-app tracking, data sale (excluded); research/model improvement (said to need its own granular consent elsewhere).
