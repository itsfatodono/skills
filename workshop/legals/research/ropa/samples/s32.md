## Document
- Shape: a spreadsheet with five tabs: 1 Tutorial; 2 Processing list (contact block plus one row
  per processing operation); 3 Template of a record of processing form (one form per operation,
  to be copied); 4 Example of a completed form (fictitious payroll); 5 Lists (drop-down values:
  transfer guarantees, countries with an adequacy flag, data-subject categories, recipient types,
  security measure types). Cell comments (red triangles) carry field help.
- Status: blank regulator model with a worked example, aimed at small businesses.
- Activities: list plus one form per operation; the example has one.
- Grouping: none prescribed; the list is the index.
- Unit of one row: one processing operation (list row), detailed in its own form.
- Scope: controller only.
- Record fields (form): Name of the processing operation; N° / REF; Date of creation; Update;
  Stakeholders (controller, DPO, external DPO's organisation, representative, joint controllers,
  each with address, phone, email); Purpose(s): main purpose and up to five sub-purposes;
  Categories of personal data, each with description and retention period; Special categories
  of personal data, each with description and retention period; Categories of data subjects;
  Recipients (type and details); Security measures (type and details); Transfers to third
  countries (recipient, country, type of guarantees, links to documents).
- Absent: legal basis, data source, systems, DPIA flag, rights.
- Register: short labels; tutorial in plain second person ("your organisation").
- Recurring elements: drop-down lists for categories, recipients, security measures, countries,
  guarantees; a Yes/No special-category flag on the list.
- Size: about 2,600 words (half of it the country list).
